# Greeting Lab Constitution

## Core Principles

### I. One observable behavior
Each feature must have one small, independently runnable user journey. A learner must be able to predict and inspect the output without a service or account.

### II. Requirements before implementation
State user-visible behavior and acceptance examples in `spec.md`; put language, file layout, and commands in `plan.md`. Tasks must point to concrete files.

### III. Evidence over completion claims
Run the documented examples after implementation. Record observed output and leave tasks unchecked until the behavior is verified.

## Development Workflow

Review the spec, plan, and tasks in that order before changing code. Update the upstream artifact first when a requirement changes, then reconcile downstream artifacts and rerun the examples.

## Governance

This constitution governs the example feature. Keep the project-root Lab instructions and the learner guide aligned with the implemented behavior. Amend this file when these principles change.
